## Collection scope

The shared tracker loads Google's asynchronous tag only when both the build target is Vercel Production and the current hostname is exactly `jjlowery.com` or `www.jjlowery.com`. App Router pages and Pages Router articles use thin adapters to the same browser-scoped instance. Successful App pages render a tracking marker after their server checks; the root guard and not-found components only pause collection. A known URL that returns a 404 cannot initialize the tag, and a stale page marker cannot count a different current path. Stale non-null callbacks on a recognized public URL leave the current dedupe/referrer state and any existing pause untouched. Only a matching successful marker can resume tracking; explicit private/404 signals still pause and reset. The URL shape alone never initializes tracking or proves a dynamic post is published. StrictMode/repeated effects, same-URL marker remounts and query/hash-only changes do not create duplicate views. A new document counts its initial view; navigation to another public path counts a new view. Later config commands use `update: true` to update safe parameters without reinitializing the tag.

Known public pages and published Post props supply canonical paths. Fixed general labels replace document/CMS titles in Analytics. Every global set/config/view overrides `page_location`, `page_title`, `page_referrer` and the six documented campaign fields. Page URLs exclude all query strings and fragments. Form fields, arbitrary URL parameters, search text, user IDs and custom user properties are not supplied by this application.

## Acquisition attribution

The first eligible public view captures acquisition once per document, after the production/hostname/route guards pass. It keeps an available external HTTP(S) referrer's origin, dropping credentials, path, query and fragment. Self-referrers, malformed URLs, local/private hostnames, IP addresses, nonstandard ports and unsupported domains are omitted. Later views use only the previously tracked canonical internal URL; a return from an excluded route does not replay the external referral. Browsers and apps can suppress referrers; the site cannot reconstruct a missing source or promise that every visit has one.

A complete, valid `utm_source` / `utm_medium` / `utm_campaign` triple becomes `campaign_source` / `campaign_medium` / `campaign_name`, independent of the canonical page URL. Labels preserve case and must contain only ASCII letters/numbers separated by hyphens, underscores or dots: maximum 64 characters, 16 per segment, no five-digit run, at most six digits, and no contact/identity/credential-like segments. Medium must also match the conventional channel list in `content/analytics-acquisition.ts`, such as `social`, `email`, `referral` or `organic`. A duplicate, missing or rejected field drops the whole triple; the referrer can still provide attribution. Query-only changes do not create a new view or replace the captured landing campaign. Campaign IDs, search terms, content labels and advertising click IDs are not copied. No acquisition data is stored by application code beyond the current document's memory.

Use public campaign labels, never personal information or secrets. Lexical validation rejects common unsafe forms; it cannot determine every label's meaning. For example, an innocuous-looking personal name would still be an inappropriate campaign label. Supported mocked examples:

| Input                                                                 | Data supplied to Analytics                                                               |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `https://www.linkedin.com/in/example?private=value` referrer          | `page_referrer: https://www.linkedin.com` on the initial view                            |
| `?utm_source=linkedin&utm_medium=social&utm_campaign=portfolio_share` | `campaign_source: linkedin`, `campaign_medium: social`, `campaign_name: portfolio_share` |
| `?utm_source=newsletter&utm_medium=email&utm_campaign=autumn-2026`    | `campaign_source: newsletter`, `campaign_medium: email`, `campaign_name: autumn-2026`    |
| No usable referrer or valid campaign                                  | Blank overrides; Google applies its attribution rules                                    |
| Email, token, duplicate or incomplete campaign fields                 | Campaign triple omitted; raw values are not queued                                       |

Google documents that `campaign_source`, `campaign_medium` and `campaign_name` override their corresponding UTMs, and that event parameters take precedence over config/global parameters. See [GA4 configuration](https://developers.google.com/analytics/devguides/collection/ga4/reference/config) and [parameter scope](https://developers.google.com/tag-platform/gtagjs/reference#parameter_precedence). All six campaign fields are set explicitly on every set/config/view; unused or rejected fields are empty strings, avoiding stale configuration merges. Google describes URL-based campaign/click-ID processing from the document-location field in [Campaigns and traffic sources](https://support.google.com/analytics/answer/11242841). Canonical `page_location` plus the explicit campaign overrides therefore preserves validated campaign values without forwarding raw query data. This is a source-supported design inference: Google's documentation does not define every empty-string fallback or guarantee that its SDK never independently reads the real URL. Mock/source checks do not establish the SDK's actual network payload.

Google processes available referral domains and UTM fields under its own acquisition/session rules. The site does not invent a source when it is missing. Link shorteners and apps may supply their own referral domain; deeper referral paths, search keywords, rejected campaign labels and unsupported attribution parameters remain unavailable. Origin-only referrals omit search-engine path/query clues, which may reduce detailed channel classification even when the referring domain is available. View processed results in **Reports → Acquisition → Traffic acquisition** using Session source / medium and Session campaign; see [Google's campaign URL guidance](https://support.google.com/analytics/answer/10917952).

Studio, design review, unknown/404 paths, local development and Vercel previews cannot initialize the tag. An in-app transition to an excluded path sets Google's `ga-disable-…` flag; returning to a valid public path resumes collection. Script loading failures disable further commands without interrupting the site.

The only application-generated event is `page_view`. Google's tag may also generate its standard session/engagement events and use first-party cookies. Google Signals and advertising personalization are disabled in the global and destination config. A `strict-origin` HTTP referrer policy and a `no-referrer` tag script policy prevent full URLs from leaking through the corresponding HTTP referrer headers.

The [public privacy page](<../app/(site)/privacy/page.tsx>) describes this automatic behavior and is linked from the shared footer. This implementation is not a legal-compliance certification or a claim that a portfolio is exempt from privacy/consent requirements.

## Destination setting prerequisite

The owner confirmed **Enhanced measurement is OFF** for the new web stream. Keep it off. Every config sets `send_page_view: false`, and the router adapters explicitly issue views automatically. Google's independent enhanced-history measurement can still produce duplicate/unredacted views if enabled; `send_page_view: false` alone does not disable it. See [Google's pageview guidance](https://developers.google.com/analytics/devguides/collection/ga4/views).

The owner should also verify that the Google tag's destination list contains only the intended portfolio GA4 destination, that Google Signals/advertising integrations are not enabled in the property, and that the stream's email redaction is enabled as defense in depth. These are account settings; this change does not inspect or modify them. See [GA4 configuration](https://developers.google.com/analytics/devguides/collection/ga4/reference/config) and [data redaction](https://support.google.com/analytics/answer/13544947).

Run `pnpm check` and `git diff --check`. The Analytics tests use actual Next router contexts with plain in-memory React and a mocked document/tag queue. They issue no Google requests and fabricate no traffic or consent. A separate Node process also exercises the actual App adapters with production React, both stale-marker orders, effect-commit synchronization, same-URL remounts and a lagging router context on an actual private URL. Separate tracker instances verify legitimate new-document counts. Tests cover automatic initial/navigation views, both routers, duplicate effects, initial and subsequent known-URL 404s, stale page markers, private transitions, hostname/build guards, title/path sanitization, origin-only referrals, validated campaigns, unsafe/duplicate/missing inputs, immutable acquisition, script failures and server-rendered privacy copy.

Browser use is prohibited for this task. Non-browser verification can confirm deployed commit/build state, public HTTP source, compiled destination/production guard and privacy-route readability. It cannot confirm Google's ingestion, actual client navigation, cookie behavior or screen-reader/visual interaction in a real visitor session.

After deployment, the owner can validate real traffic:

1. Select the **JJ Lowery** account and the portfolio property with web stream **16081799346 / G-YRGF46MB1T**.
2. Open the public production site yourself with JavaScript enabled, visit the homepage, then About, then a Blog article. No consent click is needed. A blocker or privacy extension can prevent collection.
3. Check the property's **Reports → Realtime** for that visit and `page_view` activity. Check page locations are canonical URLs without query strings or fragments. A query/hash-only change should not add a view; Studio and preview visits should not appear. For naturally arriving referral/tagged visits, check processed **Traffic acquisition** source/medium and campaign results; Realtime's active-user count alone does not prove those dimensions.
4. If nothing arrives, confirm the selected destination and Enhanced measurement state first, then check whether your browser blocked the Google tag. Source/build checks alone do not prove a received event.

This procedure uses the owner's real visit. Do not send artificial Measurement Protocol events to create a false verification result.
